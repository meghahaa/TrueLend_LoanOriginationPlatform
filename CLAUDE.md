# TrueLend — Loan Origination & Underwriting System
## Project ID: BC-AINE-003 | Domain: Banking — Lending

### Executive Summary
TrueLend is an AI-native, policy-driven loan origination and underwriting system. It enables business configuration of loan products (Personal, Vehicle, Education) and policy rules without requiring source code modifications. The end-to-end lifecycle spans product catalog definition, application submission, credit scoring, document verification, automated underwriting decisioning, EMI repayment scheduling, disbursement, repayment posting, DPD/NPA bucket recalculation, and admin overrides.

---

### Key Operational Rules (Mandatory)
1. **No-Hand-Coding Rule**: ALL production code, tests, schemas, and migrations MUST be generated by Claude Code agents under human supervision. Hand edits are strictly restricted to specs, `CLAUDE.md`, agent definitions, hooks, skills, and substrate manifests.
2. **Spec-Is-Truth Rule**: Specifications in `specs/` are authoritative. In case of disagreement between code and spec, update the spec deliberately first, then regenerate code.
3. **PR-Only Merge Rule**: No direct commits to `main`. All changes must flow through agent-reviewed pull requests using non-fast-forward merges (`git merge --no-ff`).
4. **Synthetic-Data Rule**: Use dummy synthetic data exclusively. Never write confidential banking credentials or real PII.

---

### Non-Negotiable Engineering Constraints
- **Fixed-Point Financial Math (NFR-01)**: All monetary values (principal, interest, EMI, balance) MUST use fixed-point arithmetic (`BigDecimal` / `decimal`). NEVER use floating-point types (`float`, `double`).
- **Policy & Schedule Immutability (NFR-02)**: Approved policy versions and generated repayment schedules are append-only. UPDATE and DELETE operations are forbidden.
- **PII Protection & Sanitization (NFR-03)**: Synthetic PAN, Aadhaar, and salary document contents must NEVER be written to logs or stdout.
- **Authentication & Audit Logging (NFR-04)**: Controller-level authentication boundary must be enforced. Underwriter actions (approvals, overrides, document decisions) must log user ID, timestamp, and reason code.
- **Append-Only Migrations (NFR-05)**: Database schema and policy migrations are append-only.
- **Structured JSON Logging (NFR-06)**: All logs must be output in structured JSON format containing a unique request correlation ID.
- **Startup & Health Check (NFR-07)**: `/actuator/health` or `/health` must respond with HTTP 200 within 1 second of successful startup.
- **Automated Architecture Tests (NFR-08)**: Structural rules (layer isolation, EMI invariant formulas) must be enforced via ArchUnit / dependency tests.

### Functional Acceptance Criteria Reference
| ID | Title | Summary |
|---|---|---|
| **AC-01** | Loan Product Catalog | Support >=3 products (Personal, Vehicle, Education) with distinct rule sets from versioned policy files. |
| **AC-02** | Application Intake & Checklist | Customer applies for loan; required document checklist generated dynamically per product. |
| **AC-03** | Credit Scoring Stub | Deterministic credit scoring from age, income, and credit history flags. |
| **AC-04** | Underwriting Decisioning | Decision returns `AUTO_APPROVE`, `AUTO_REJECT`, or `MANUAL_REVIEW` with policy reason codes. |
| **AC-05** | Minimum Income Threshold | Application throws `PolicyViolationException` when income < minimum policy threshold. |
| **AC-06** | Document Verification Queue | Underwriter marks documents `VERIFIED` or `REJECTED` with audit reason. |
| **AC-07** | EMI Repayment Schedule | On approval, EMI schedule generated using standard formula where sum(principal + interest) == total payable. |
| **AC-08** | Disbursement Record | Disbursement records released amount and stubbed funding source details. |
| **AC-09** | Repayment Posting & Bucketing | Repayment posting reduces principal; bucket recalculated (`CURRENT`, `DPD-30`, `DPD-60`, `DPD-90`, `NPA`). |
| **AC-10** | Admin Override & Audit | Admin lists applications, filters by status/product, overrides `AUTO_REJECT` with audited comment/reason code. |

### Layering Hierarchy
- `src/domain/`: Core business models, policy rules, immutable entities, value objects. No dependencies on external frameworks or controllers.
- `src/services/`: Business services, EMI calculators, underwriting engine, repayment posting. Depend only on domain.
- `src/controllers/`: REST API endpoints, DTO mapping, auth boundary enforcement, correlation ID logging.
- `frontend/`: UI components (React/Angular/Vue), responsive views for application intake, underwriter workbench, and admin override.
- `tests/`: Unit tests, architecture tests (ArchUnit), integration tests, Playwright E2E UI tests.
